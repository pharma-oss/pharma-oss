# 嘘をつかない厳格な開発・検証スキル (honest-verification)

このスキルは、開発・検証において表面的な数字や取り繕いを排除し、真の品質と安全性を確保するための鉄則を定めたものです。

## 1. 型検査の実測
- `npx tsx` は esbuild により高速動作するが型チェックを行わない。
- 必ず `npx tsc --noEmit` を実効実行し、コンパイルエラーが 0 件であることを自身の目で確認する。

## 2. 真正なテストカバレッジの作成
- テストコード内でコンポーネントやロジックの挙動を自前で再実装（`mockData.filter(...)` 等）してテストを通す行為（偽カバレッジ）を厳禁とする。
- 検証対象のロジックは純粋関数（例: `calculateFilteredDrugs`）として切り出してエクスポートし、テストコードから直にインポートして本物の関数をテストする。

## 3. ドメイン仕様と副作用の確認
- 修正を行う際、フラグやモードごとのドメイン仕様（例: `prescribed` モードにおける一般名処方【般】レコードの必要性、`dispensed` モードでの除外、全件マスタ検索など）を理解し、片方の修正が他方のモードの破壊にならないよう多角的に検証する。

## 4. ドキュメントの誠実な更新
- コードレベルの実装と型検査・テストが揃わない段階で、ドキュメントのステータスを「完了」と書き換えない。

## 5. ロックファイルとコマンド実行の完了確認
- `package.json` 編集時は `npm install` / `npm ci` の完了と `package-lock.json` の差分更新・ `npm ci --dry-run` の通過を必ず自機で確認する。依存型の不一致を `npx tsc --noEmit` で即時修正する。

## 6. スタイリング規約の遵守とUI実表示確認
- プロジェクト未導入の CSS フレームワーク（TailwindCSS等）を使用せず、既存のスタイリング規約（Vanilla CSS, CSS変数, インラインstyle）を適用する。表示崩れや無地状態がないかコンポーネントまたは画面描画を自ら確認する。

## 7. 依頼されていない領域への独断的仕様・安全設計変更の厳禁
- 指示された範囲を超えて、基盤の競合解決・安全設計・ロジックを独断で書き換えてはならない。
- UX改善や課題指摘を受けた際、頼まれていない安全基盤や競合解決アルゴリズム（例: ハブ正本優先＋人間レビューから暗黙の Last-Write-Wins / 自動ファストフォーワードへの置き換え）を「気を利かせて」勝手にコード変更してはならない。
- 医療データ（患者アレルギー・副作用・処方・薬歴等）の安全保護設計は最優先とし、変更の必要性を感じた場合は独断で実装せず、必ず事前に提案・対話として提示し合意を得る。
