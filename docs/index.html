Why pharma-oss

便利さのために、患者安全とデータ主権を犠牲にしない。

pharma-oss は「金科玉条（不可侵の十箇条）」を最上位の設計規範に据え、現場のスピードと医療安全・個人情報保護を両立させています。

PILLAR 01 — LOCAL-FIRST & ZERO LEAKAGE

患者データは店舗から出ない。サテライト端末には残さない。

単独端末運用では、患者データはブラウザ内DB（IndexedDB）に暗号化保存され、ネットが切れても業務は止まりません。 店舗内で複数端末を使う場合も、正本はメイン端末（node:sqlite + AES-256-GCM暗号化）に集約し、サテライト端末はメモリ専用（ディスク保存ゼロ）で動作します。

RxDB + IndexedDB暗号化 SQLite WASM/OPFSマスタ PWAオフライン対応 メモリ専用サテライト同期
PILLAR 02 — FAIL-SAFE WORKFLOW

未完了なら、先に進めない。勘で補完しない。

GS1バーコード未照合、薬歴の構造化チェック未了、廃止薬・薬価未設定・レセ電コード欠落などの不備が残ったままでは、完了確定やUKE出力をシステムが停止します。 単位未設定時の勝手な 「錠」 補完や生年月日不明時の仮計算を排し、判定不能なものは正直に警告します。

GS1現物照合ゲート 二重の請求前チェック 剤形・数量セマンティクス一本化 出力済み請求の編集ロック
PILLAR 03 — PHARMACIST SOVEREIGNTY

最終判断は薬剤師が下す。AI補助は候補提示に徹する。

AI補助は外部LLMへ一切通信しないローカル決定論エンジンです。処方とアラートを根拠にSOAP下書きを unconfirmed（未確認） として提示し、薬剤師が承認・修正して初めて確定記録になります。 未確認の下書きはトレーシングレポート等の院外文書から自動除外され、店舗ごとに標準 / 制限 / 停止を選べます。

外部LLM送信ゼロ 採否の監査ログ記録 院外文書への未確認流出防止 標準/制限/停止ポリシー切替
PILLAR 04 — TAMPER-EVIDENT & ZERO DATA LOSS

記録は改ざんできず、壊れてもデータを失わない。

主要操作は端末別ハッシュチェーン署名付き監査ログに記録し、S3 Object Lock（WORM）への外部保全ジョブに対応。 DB初期化失敗時も自動削除（旧自己修復）を行わずデータを保護し、世代管理つき暗号化JSONバックアップ・SHA-256読み戻し照合・緊急復旧鍵シート印刷で確実な復旧経路を残します。

端末別ハッシュチェーン監査ログ S3 Object Lock (WORM) 不変の請求スナップショット DB暗号鍵エスクロー印刷

Daily Workflow

受付から請求・発注・端末同期まで、現場の1日の順番のまま。

画面の都合ではなく、薬局の業務動線に沿って設計されています。すべての工程に抜け漏れを防ぐ安全装置が組み込まれています。

STEP 01 — 処方箋受付・資格確認・名寄せ

処方箋を読む。原本と並べて人が確認する。

ブラウザ内OCR（Tesseract.js）・JAHIS処方箋QR（カメラ / 画像 / ハンディスキャナー）・資格確認端末の連携フォルダからのマイナ資格確認結果XML取込・手入力受付に対応。 読み取り結果は処方箋画像と並べて確認でき、氏名＋生年月日で既存患者へ自動名寄せします。

  • 厚労省 電子処方箋用法マスタ（1,803件）＆支払基金医薬品マスタ — コードの自前発番を排し、内滴用法の厳格チェックや一般名処方【般】検索に対応
  • 複数公費（第1〜第3公費）の安全保護 — 患者情報編集時も2件目以降の公費負担医療情報が消失しない保護設計
  • 未実装機能の誠実な明示 — 電子処方箋管理サービス接続など未実装のボタンは「（未実装）」と表示して無効化し、現場が「故障」と迷う時間をゼロに
ブラウザ内OCR JAHIS QR取込 マイナ結果XML取込（連携フォルダ） 名寄せ・重複統合 電子処方箋取得（未実装明示）

STEP 02 — 調剤・ピッキング・機器連携

棚番地順で集め、GS1データバーで現物を照合する。

処方内容から棚番地順のピッキングリストを自動生成し、GS1データバーで医薬品（GTIN/JAN）・使用期限・ロット番号の一致をリアルタイム照合。 棚不足があればその場で記録でき、在庫管理の「発注ワークベンチ」へ自動連動します。

  • 既存ピッキングシステム連携 — 棚番地・JAN・必要量・ロット候補入りの指示CSV書き出しと、結果CSV/TSV取込（完了→照合済、不足→不足記録）
  • NSIPS準拠の調剤機器・POS連携 — 施設内コネクタ経由での処方送信・差替・取消と、連携IDによる二重送信防止
GS1データバー照合 ロット・使用期限チェック 棚不足→発注候補連動 NSIPS調剤機器連携

STEP 03 — 電子薬歴・服薬指導・安全監査

前回との違いが見える。多層チェックでリスクを逃さない。

4パネルSOAPエディタと、服薬状況・残薬・副作用・後発品変更意向・お薬手帳の構造化チェックを1画面に集約。 前回Do・処方差分・薬歴タイムラインを見比べながら、根拠付きのAI補助下書きを薬剤師が確認・編集して確定できます。

  • 多層臨床安全チェック — 患者アレルギー/副作用歴との一般名ファジー突合、PMDA添付文書由来の併用禁忌・相互作用警告、同効薬重複検知
  • 疑義照会・トレーシングレポート・服薬フォロー — 疑義照会の構造化記録、服薬情報提供書（未確認AI下書きは自動除外）の作成・印刷、来局後のフォローアップ管理
4パネルSOAP＋構造化チェック PMDA相互作用・禁忌チェック アレルギー一般名突合 トレーシングレポート

STEP 04 — 算定・帳票印刷・公式仕様UKE請求

チェックを通らないレセプト（UKE）は、出さない。

令和8年（2026年）調剤報酬ベースの自動算定（薬剤調製料・調剤管理料・服薬管理指導料・各種加算、算定OFF理由の監査記録、調剤日基準の薬価履歴解決）を実行。 支払基金の記録条件仕様（令和8年6月版・調剤用）に基づく単票公式UKE点検・プレビューと月次一括UKE出力（Shift-JIS）を備えています。

  • 二重の請求前ゲートと公式仕様PDF自動突合 — 廃止薬・薬価未設定・レセ電コード欠落・必須レコード（SN/JD/MF/ST等）・合計点数を検査し、不備があれば出力を停止して指摘CSVを出力
  • 不変スナップショットと返戻ライフサイクル — UKE出力時点のスナップショットを不変保存し、出力後の誤編集をロック。返戻結果取込・修正メモ・再請求まで追跡
令和8年調剤報酬算定 支払基金 公式UKE点検・出力 請求スナップショット＆差分CSV 返戻・再請求ワークフロー

STEP 05 — 在庫管理・発注ワークベンチ・棚卸

処方不足も期限切迫も、発注ワークベンチへ自動集約。

ロット・使用期限・棚番地単位の在庫管理に加え、受付中・調剤中の処方不足や発注点割れ、使用期限切迫を「発注ワークベンチ」へ統合検知。 同一薬効の代替薬候補の確認や他店舗からの分譲融通、患者名を含まない安全な発注CSV出力までワンストップで行えます。

  • 卸データ入荷インポート＆納品書OCR読取 — GS1/JANバーコード入庫、卸CSV取込、納品書OCRで入庫登録を省力化
  • 麻薬・向精神薬棚卸＆デッドストック検知 — 帳簿残高と実在庫の突合記録、不動在庫の抽出、棚マスター管理を標準搭載
発注ワークベンチ 個人情報なし発注CSV 納品書OCR・卸データ取込 麻薬・向精神薬棚卸

STEP 06 — 複数端末サテライト同期・競合レビュー

受付窓口も調剤室も。サテライト端末には患者データを残さない。

複数端末で運用する場合、メイン端末（集約ハブ）に患者データを一極集約し、窓口や無菌室のサテライト端末はRxDBメモリストレージのみで稼働します。 端末の追加・廃棄はメイン端末でのトークン発行・失効だけで完結し、端末紛失時の情報漏えいリスクを根本から断ちます。

  • メイン停止中も業務継続 — 一時的な通信断でもサテライト側で暗号化未送信キューに保持して入力継続し、再接続時に自動送信
  • ハブ正本優先＋薬剤師レビュー — 複数端末から同一データが同時更新された場合、暗黙の上書き（Last-Write-Wins）は行わず、競合レビュー画面で薬剤師が安全に確認・反映
メイン端末正本集約 サテライト端末ディスク保存ゼロ ワンクリック端末トークン失効 ハブ優先＋人間競合レビュー

Architecture & Principles

クラウドに依存しない技術スタックと、不可侵の設計原則。

Next.js App Router と RxDB（IndexedDB暗号化）＋ SQLite WASM/OPFS を組み合わせ、ブラウザ単体でも店舗内LAN複数端末でも軽快・安全に動作します。

Getting Started

3分で、架空のデモ患者を1人さばけます。

Node.js 環境があれば4行のコマンドで起動します。デモ受付データは請求（UKE）や外部機器連携から自動除外され、いつでもワンクリックで片づけられます。

zsh — quickstart 
git clone https://github.com/pharma-oss/pharma-oss.git
cd pharma-oss
npm install
npm run dev
# → ブラウザで http://localhost:3000 を開く

おすすめ ルートA：パスワード設定なしで今すぐ体験

  1. http://localhost:3000 を開き、初期画面の「デモ患者で体験を始める」（または右上の「3分デモ」）をクリックします。
  2. 体験モード（パスワード未設定）でログイン不要のまま、架空のデモ患者「デモ患者 みどり（68歳・ロキソプロフェン副作用歴あり・3剤処方）」の薬歴画面が開きます。
  3. ピッキング支援（GS1照合・棚不足記録）→ SOAP薬歴入力・構造化チェック → 帳票印刷・公式UKE点検まで、実際の画面を一通り操作できます。

本番想定 ルートB：管理者パスワードを設定して体験

  1. 初回起動画面で管理者パスワード（8文字以上）を設定してログインします。
  2. 画面右上の「3分デモ」を開き、最後のステップで「デモ患者で体験を始める」を押します。
  3. 練習が終わったら、ダッシュボード上部の「デモデータを片づける」ボタンでデモ患者・受付・在庫をすべて一括削除できます。
Q. インターネットが完全に遮断された環境でも動きますか？
はい。一度起動・PWAインストールすれば、患者データ（IndexedDB）、医薬品・用法マスタ（SQLite WASM/OPFS）、処方箋OCR（Tesseract.js）、GS1/QR読取（@zxing）、AI補助SOAP下書き、帳票印刷、UKE出力まですべてブラウザ内でオフライン動作します。
Q. 複数台のPCやタブレットで同時に入力できますか？
はい。「サテライト端末同期モード」により、メイン端末1台をハブ（PHARMACY_SYNC_ROLE=hub）として正本DB（AES-256-GCM暗号化）を保持し、窓口や調剤室のサテライト端末（PHARMACY_SYNC_ROLE=satellite）からLAN経由で同期できます。サテライト端末はメモリのみで動作しディスクに患者データを残さないため、タブレット等の紛失時も安全です。詳細は サテライト端末同期設計書 をご覧ください。
Q. 薬価改定や新薬・経過措置のマスタ更新はどう行いますか？
アプリ内の「設定 > マスタ更新」から、支払基金が公開する医薬品マスタCSV/ZIPをそのまま取り込めます。取込時には変更差分CSVとロールバック用JSONが自動生成され、誤って古いマスタファイルを取り込んでも現在薬価が巻き戻ったり廃止薬が復活したりしない保護ロジックが働きます。また、地方厚生局の公開ファイルからの医療機関マスタ都道府県別差分マージにも対応しています。
Q. 既存のレセコンやピッキング機器と併用・段階移行できますか？
はい。患者・薬歴データの移行CSV取込（事前検証・トライアル受入チェック付き）に対応しているほか、既存ピッキングシステム向けの指示CSV出力・結果CSV/TSV取込、およびNSIPS準拠の調剤機器・POSコネクタ連携を備えています。まずは電子薬歴・ピッキング照合・在庫発注管理から使い始め、段階的に運用を広げることも可能です。
