#### 測定コマンド（旧版は当てになりません）

引き継ぎ書の旧版に載せていた測定コマンドは、第 2 条件 `grep -qE "\.(ts|tsx|mjs)['\"]"` が
**本リポジトリの import 規約（`from './foo.ts'`）に全件マッチしてしまい**、
`package.json` を読むだけのテストまで数えていました。実質「readFileSync を呼ぶテスト全部」の数です。
以下を使ってください（readFileSync の対象がソースファイルであるものだけを数えます）。

```bash
find src -name "*.test.ts" | while read f; do
  n=$(grep -cE "readFileSync\(new URL\('[^']*\.(ts|tsx|mjs|css)'" "$f")
  [ "$n" -gt 0 ] && echo "$(grep -c 'assert\.' "$f")  $f"
done | sort -rn
```

## 5. この作業で得た教訓（次の人へ）

このセッションで見つかった実装バグは、**すべて `tsc` / `build` / 全テストを通過していました。**
見つかったのは、画面を実際に描画して目で見たからです。

| 見つかったバグ | 見た目 | 検出方法 |
|---|---|---|
| 印刷 CSS 51 クラスの消失 | 正常 | PNG を開いた |
| 緊急復旧シートがダミー鍵を印刷 | 正常（綺麗にレンダリング） | PNG を開いて Fingerprint を読んだ |
| AI 下書き承認の監査ログ未記録 | 正常（バッジもトーストも出る） | 監査ログの中身を DB から dump した |
| 監査ログ表が常に空 | 「記録はありません」と表示 | 表の行数を数えた |

### 具体的な注意点

1. **`tsx --test` は型検査をしません。** テストを足したら必ず `npx tsc --noEmit` を単独実行してください。
   このセッションでも、テストが全通過したあとに tsc が 3 件のエラーを出しました。

2. **`npm test` を選択実行で代替しないでください。** 触ったファイルだけ回すと、
   触っていないファイルが壊れます。実際に P2-1.5 で UKE 出力の監査ログテスト 5 件が
   壊れたまま「完了」報告が出ました。

3. **スクリーンショットは「撮れた」ではなく「何が写っているか」を確認してください。**
   セレクタが一致しないと、多くのスクリプトは黙って同じ画面を撮り続けます。
   キャプチャスクリプトでは `if (btn)` ではなく `if (!btn) throw` を使ってください。
   撮り終わったら MD5 が全部異なることを確認してください。

4. **モードで分岐する画面に注意。** `TerminalSyncPanel` は standalone / satellite / hub で
   描画内容が変わり、standalone では 3 クラスしか描画されません（hub は 48）。
   `.claude/launch.json` の `yakureki-hub` / `yakureki-satellite` で各モードを起動できます。

5. **運用レビュー CLI の `exit 1` はクラッシュではありません。** 「レビュー未達」を表す設計です。
   詳細は `docs/ops_review_ledger.md` §0。
