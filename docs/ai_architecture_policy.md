# AIアーキテクチャおよび安全性方針（AI Architecture & Safety Policy）

## 1. AI 補助機能の基本設計方針

pharma-oss におけるすべての AI 補助機能（SOAP 下書き補助、処方入力監査、返戻リスク予測、在庫欠品予測、服薬フォロー候補抽出等）は、以下の基本方針に基づいて設計・実装されています。

### (1) 決定論的ルールベースによる稼働と LLM 非使用の記録
- **現状の実装方式**: 本システムは、外部またはローカルの LLM（大規模言語モデル: OpenAI, Google Gemini, Anthropic, Ollama 等）へのテキスト送信・API 呼出しを行っていません。すべての提案は、厚生労働省告示・医薬品マスタ・監査ルールセットに基づく**決定論的ルールベースおよびテンプレート展開ロジック**によって生成されます。
- **プロンプトインジェクション防御に関する方針**: 外部 LLM を使用していないため、プロンプトインジェクション（例: `Ignore previous instructions` 等のプロンプト隔離・XMLカプセル化）対策は不要として意図的に除外しています。
- **将来 LLM を導入する際の必須見直し事項**: 将来的に生成 AI / LLM API を導入する場合は、本方針を見直し、外部テキスト（処方箋 OCR 文字列、患者問診票、患者コメント等）をシステムプロンプトから分離・無害化するプロンプト境界（Prompt Boundaries）およびサニタイズ層を新設すること。

---

## 2. 実在する入出力リスクの多層防御

LLM 特有のリスクではなく、実務・ブラウザ運用における実在リスクに対して以下の対策を講じています。

### (1) CSV 数式インジェクション（CSV Formula Injection）防止
- 外部エクスポートされる CSV ファイル（患者服薬情報、マスタ、操作ログ等）のセル値において、表計算ソフト（Excel, Google Sheets 等）で数式として実行され得る危険文字（`=`, `+`, `-`, `@`, タブ `\t`, 復帰 `\r`）の先頭付与を検知した場合、シングルクォート（`'`）を前置して無害化（`src/lib/csv_escape.ts`）。

### (2) 印刷 HTML の XSS 防止
- サーマルプリンタ用レシート（`picking_receipt.ts`）、分譲記録書（`stock_transfer.ts`）、服薬情報提供書（`tracing_report.ts`）などの HTML 生成において、患者名・薬品名・ロット番号等の全可変パラメータを `escapeHtml` により確実にエスケープ。

## 3. 出力管理と薬歴（法定保存文書）の完全性

### (1) AI 下書きの未確認（Unconfirmed）ライフサイクル管理
- 自動生成された SOAP 下書きは、薬剤師が内容を確認・修正・承認するまで `aiStatus: 'unconfirmed'` として区別されます。
- 薬剤師による明示的な承認操作（または手動編集による確定）を経て初めて `aiStatus: 'approved'` / `aiStatus: 'modified'` へ遷移し、確定記録として扱われます。
- 未確認の AI 下書きが残存している状態での処方完了・薬歴確定はシステム上で警告・抑止されます。

### (2) 院外文書（トレーシングレポート）への未確認テキスト流出防止
- 服薬情報提供書（トレーシングレポート）の生成・抽出処理（`src/lib/tracing_report.ts`）において、`aiStatus === 'unconfirmed'` の未確認エントリは抽出対象から自動除外されます。医師へ送付される院外文書には、薬剤師が承認した内容のみが掲載されます。

### (3) 法定保存文書の来歴管理（マイグレーション方針）
- RxDB スキーマ v4 マイグレーション適用以前の過去薬歴データは、客観的事実として `origin: 'legacy_unspecified'`（由来記録なし）として保持し、過去記録に遡及して虚偽の「薬剤師手書き（manual）」属性を付与しない。
- スキーマ v4 のマイグレーション適用日時は監査ログ等に記録され、来歴管理の開始境界を証明可能とする。
