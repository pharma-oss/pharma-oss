### 直したもの

| # | 症状 | いつ起きるか |

| 1 | 遡り取込で版が積まれない（§4.3-3） | 遡り取込のみ |

**2番が一番影響が大きいです。** マスターの現在薬価には適用開始日が付いてこないので、
履歴が空のまま最初の改定を積むと旧薬価がどこにも残りませんでした。結果、改定日より前の
調剤が新薬価で算定されます。**これは薬価履歴が防ぐために作られた事象そのもので、
2回目の改定までは起きたままでした。**

対処として `effectiveFrom` を省略可能にし、「開始日不明の版」を表せるようにしました。
日付を捏造せずに旧薬価を残せます。画面には `開始日不明・最初の改定より前` と出ます。

```
drugs               7 → 8   priceHistory[].effectiveFrom を required から外した
prescription_items 16 → 17  drugPriceOverride.effectiveFrom を required から外した
```

移行はどちらも `keepDocument`（既存の版はすべて日付を持っています）。

### 取込済みより古いマスターファイルへの守り（`06afe2e`）

**「薬品ごとには決められないが、ファイル単位では決められる」** というのが答えでした。
本書で「実装だけでは決められない」と書いたのは誤りです。

「変更年月日」はその行が最後に変わった日なので、**ファイル全体の最大値がそのファイルの
新しさ**になります。取込済みの版の最大値より古ければ、そのファイルは手元のデータより
前の状態を表しています（`reviewDrugMasterVintage`）。

古いファイルと分かった場合の扱いです。

| 薬品 | 扱い |
|---|---|
| 版を持っている | そのまま取り込む。現在薬価は最も新しい版から決まるので巻き戻らない |
| 版を持っていない | **薬価に触れない。** 現在薬価の適用開始日を持っていないため |

版を持たない薬品を「現在薬価として書く」と巻き戻し、「古い版として置く」とその日以降の
調剤を誤ります。どちらも推測なので、触らずに件数を残す方を選びました。

件数は取込の監査ログに入り、古いファイルのときは警告も出ます。
**取り込んだ件数より少なく反映されたことが黙って進むのが一番まずいためです。**

判定はファイルに載っている薬品の版から行います。実際のマスターは2万行規模で版を持つ
薬品が必ず含まれますが、**1件も含まれないファイルでは判定できません。**
その場合は「古い」とは言わないので、取込が止まることはありません。

古いファイルでは、**名称・YJコード・廃止フラグも据え置きます**（`933e208`）。
これらには適用開始日が無く、マスターの行は「今こうである」としか言っていないためです。

**特に廃止フラグは、これまで取込のたびに無条件で書き換わっていました。**
古いファイルを取り込むと廃止済みの薬品が復活し、廃止コードのまま調剤・請求してしまいます。

### ロールバックが薬価履歴を消していました（`933e208`）

`drug_master_version.ts` の `DRUG_FIELDS` に `priceHistory` が入っていませんでした。
スナップショットが版を落とす → ロールバックJSONの復元行も版を持たない →
復元は `bulkUpsert`（ドキュメント全置換）なので、**戻した薬品の履歴が丸ごと消えます。**

実測です（取込 → ロールバック）。

```
修正前: 版 3件 → 0件
修正後: 版 3件 → 3件
```

版が無くなると過去の調剤が現在薬価で再計算されます。**薬価履歴が防ぐために作られた
事象そのものが、ロールバック1回で起きます。**

同じ理由で「版だけが変わった薬品」が変更として拾われず、その取込は元へ戻せませんでした。

`DRUG_FIELDS` に足すときは**値で比較する**必要があります（他の項目は `!==` で
比べており、中身が同じ配列でも参照が違うため、毎月の取込で全薬品が「変更あり」になります）。

### 実画面での確認

薬価の版の選択 UI が実際に描画されることを確認しました（e2e が保存する `page.html`）。
